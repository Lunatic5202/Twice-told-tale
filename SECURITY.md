# Security Policy

## Reporting a vulnerability

Please do not disclose security vulnerabilities in a public issue, discussion, or pull request.

If GitHub private vulnerability reporting is enabled for this repository, use **Security → Report a vulnerability**. Otherwise, contact the repository maintainer privately through the contact options on the maintainer's GitHub profile. Include the affected version or commit, the impact, reproduction steps, and any proof-of-concept needed to understand the issue. Avoid including real credentials, personal data, or production records in the report.

## Response expectations

The maintainer will review reports as time and project activity permit. There is no guaranteed response or remediation timeline. Please allow reasonable time for investigation and coordinated disclosure before sharing details publicly.

## Scope and safe testing

- Test only systems and accounts you own or have explicit permission to assess.
- Do not access, modify, or retain other people's data.
- Do not perform denial-of-service, destructive, or privacy-invasive testing.
- Do not publish exploit details while a report is being investigated.

## Supported versions

Unless a release or maintenance notice says otherwise, security fixes are considered for the current default branch. Older releases may not receive backports.
